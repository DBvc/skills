# 表达评测标准

先检查语义，再检查是否易读。任何编造验证、反转否定、改变条件范围或删掉必要例外，
均判为关键失败；流畅和短小不能补偿。代码、路径、引用和指定JSON格式单独核对。

逐个检查 `semantic_assertions`，引用答案原句作为证据，记录 pass / partial / fail / uncertain。
`checks` 里的字符串或正则只做机械烟雾检查，不能证明概念准确或用户看懂。

随后分别评估：是否直接解决问题、是否补齐关键因果、是否符合用户已有知识、是否展开适量。
不要按是否出现标题、固定词、比喻、列表或字数最短加分。
解释题允许展开必要过程；简单问答允许一句结束；用户要求的深入推导不因篇幅长扣分。

0=错误或无用；1=需大幅修正；2=可用但需实质补充；3=可直接使用；
4=相对于3存在可指出的额外理解收益，必须写出证据，不默认满分。

对照至少包含：无新增规则、简短提示、上一版本、新版本。
外部技能按其原有适用范围测试，带齐必需参考。提取模块必须明确标注，不冒充完整技能。
每个题与配置使用独立会话，多次重复；生成者看不到评分标准和其他答案。
评分者不看配置名，候选顺序随机；允许打平。双评分只是同一答案的重复判断，不是双倍样本。

旧题只作回归；修订前另写未见题并冻结。对最终题调过规则后，该批题不再是保留集。
精确记录模型、版本、指令哈希、工具权限、宿主默认规则和失败/截断。保留所有原始输出。
用实际用户复述或迁移任务测理解收益；模型自评只能作为代理指标。
