# DBX Epistemic Audit / 观点与证据审计

版本：0.1.0。状态：可迁移试用的候选版本；尚无真实模型对照结果。

## 解决什么

输入一个观点、论证、文章、截图或一组明确提供的信息来源，检查最可能影响结论的证据缺口和推理跨越，并实际补做可用的关键检验。

目标是改善判断的可纠错性，不是把用户说服到“中间立场”，不是证明用户有偏见，也不是制造更长的正反双方报告。

有效结果可以是：保留原判断、证据增强、缩小范围、修改解释、否定判断或暂时无法判定。没有发现重要问题，也是一种有效结果。

## 使用

在支持 `$skill` 的 Codex 界面中显式调用：

```text
$dbx-epistemic-audit

观点：我看到几家团队说迁移到框架 A 后效率提高了，所以我们的项目也应该迁移。
请检查哪些信息真正会改变这个判断，而不是机械罗列优缺点。
```

也可以选择该 skill 后输入观点。其他宿主使用各自的技能选择方式，不假定 `/epistemic-audit` 命令存在。

```text
$dbx-epistemic-audit
只根据下面的材料检验论证，不联网。请区分“结论可能对”和“理由是否成立”。
[粘贴观点与材料]
```

```text
$dbx-epistemic-audit
这是我主动提供的十篇文章。检查来源依赖、样本和关键缺口。
不要根据这些文章推断我的全部阅读习惯，也不要保存个人信念档案。
```

未设置立场、原始置信度、完整背景时也可以工作，不要求先填问卷。缺少观点或目标材料时才需要补充。

## 第一版边界

采用手动优先策略。`agents/openai.yaml` 关闭 Codex 隐式调用；未识别这一元数据的宿主靠 description 和调用边界约束，效果需在该宿主单独测试。

本体是无状态、只读协议。没有后台采集、浏览历史读取、长期信念账本、自动订阅调整、外部写回或多 Agent 辩论编排。

可用检索工具会用于必要的事实检验；无工具、来源不可访问或用户禁止联网时，降级为明确标注边界的逻辑/材料审计。技能不附带搜索服务凭据，不硬依赖 MCP 或其他 DBX skill。

## 文件与加载

`SKILL.md` 是运行内核；`references/` 是按需证据规则和边界示例；`agents/openai.yaml` 是 Codex 元数据。

`evals/` 只供维护与验证，包括仓库兼容的 JSON 用例、成对变形测试、人工评分准则和离线包检查工具。普通任务不应加载该目录。

## 验证

从 skill 目录运行，Python 3.10+，仅标准库：

```bash
python3 evals/validate.py .
python3 -m unittest discover -s evals -p 'test_*.py' -v
```

这些命令只检查包结构、测试格式和检查器行为，不运行 LLM，也不能证明技能有效。

迁入仓库后，沿用仓库现有验证器和 skill-architect 的输出断言 runner，具体流程见 [evals/README.md](evals/README.md)。对照试验通过前不得标注 L6 或声称比基础模型更好。

## 已知局限

这是对一次判断的辅助检验，不是对用户是否“陷入信息茧房”的可靠诊断。源头材料可能缺失或不独立，LLM 对证据质量和因果结构的判断也可能出错。

文字断言只能充当回归报警器，不能充当客观性、去偏见或事实正确性的裁判。语义验收必须核对来源和输出理由。
